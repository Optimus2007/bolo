# Model card: Bolo Tiny

Bolo Tiny reads a short Hinglish command (Roman, Devanagari or mixed script) and returns what the user wants
done: an intent such as `open_terminal`, plus the details it needs, such as `folder: rust learning`.
It was trained from scratch for this project and is small enough to run on a cheap phone.

## At a glance

| | |
|---|---|
| Task | Intent classification and slot tagging for desktop voice commands |
| Size | 0.69M parameters, 0.8 MB as int8 ONNX |
| Speed | about 0.4 ms per command in Python on an M2 CPU, about 1 ms with ONNX on one thread |
| Languages | Hinglish in Roman script, Devanagari, or a mix of both |
| Intents | open_terminal, open_claude_in_folder, call_contact, open_app, check_status, open_file_or_folder, set_volume, set_brightness, none |
| Licence | Apache 2.0 (code and the `phono_views_aug` weights) |
| Recommended checkpoint | `phono_views_aug` (trained without the research only paraphrases) |

## How it works

Every word is broken into short overlapping chunks of 2 to 4 characters, taken from four views of the same word: the word as written, its Roman
transliteration, a phonetic key that folds common spelling variants together (kholo and kolo look the same), and a
consonant skeleton. We call this PhonoHash. The chunks are hashed into 8,192 buckets and feed a two layer Transformer (width 96) with one head for
the intent and one for the slot tags. A temperature calibrated confidence lets the system abstain.

Training data is the Bolo synthetic command set (5,000 training rows) with slot values replaced by random pseudo
words, word dropout, filler words, and the same sentence shown in all three scripts.

## Results (synthetic and paraphrased text, not real speech)

| Test | Exact match |
|---|---|
| Synthetic test, unseen names | 87.7 ± 0.7 (3 seeds) |
| Synthetic test, after grounding to the device | 95.8 |
| Paraphrased test (rewritten by a local LLM, reviewed) | 69.9 ± 3.1 |
| False action rate on the synthetic test | 6.7% |

What helped, measured by ablation: PhonoHash (+5.0), data augmentation (+6.4), multi script views (+2.5).
What did not: a cross script consistency loss (−1.4) and distillation from MuRIL (−4.0). We report both.

Speech results (real and synthetic audio through a speech recogniser) are in `results/speech/`.

## Limits you should know about

1. It only knows the nine intents above. Anything else should come back as `none`, and usually does, but not always.
2. It loses a lot of accuracy on phrasings it never saw (about 18 points on the paraphrased test). Real people will
   phrase things in ways our templates do not cover.
3. All training data is synthetic. It has not been trained on any real user's speech or text.
4. When the spoken folder or contact does not exist, grounding still snaps to a similar name about 29% of the time.
   Anything destructive should always be confirmed by the user.
5. It never executes anything by itself. The calling program decides what to run.

## Variants that are not for release

`phono_views_aug_para*` was trained with paraphrases generated by Qwen2.5 3B Instruct, which is under the Qwen Research
Licence. Those checkpoints and that data are kept for research and evaluation only until the licence question is
settled. The recommended checkpoint above does not use them.
